# QQ 人格机器人 · 设计规格 v0.1

> 四轮需求澄清后的结论稿。
> 定位：**一个住在群里的成员**——能听、会说、会看图、会画图，没人理它时也会自己找话聊。
> 记忆模型另见 [./memory-model.md](./memory-model.md)。

---

## 1. 定位

| 维度 | 结论 |
|---|---|
| 本体 | **全局单例**，一个人格走天下，声音/语气/价值观永远一致 |
| 记忆 | **L1 跨群个人 + L2 群内隔离**，两者都要，严格隔离 |
| 首发 | 熟人小群（≤20 人），容忍度高、反馈真实 |
| 主动性 | 会自己找话聊，治理规则先于功能 |
| TTS | 按需触发（LLM 决定），但主动发言禁语音 |

一句话架构陈述：**LLM 是决策者，但不是授权者。**

最终动作 = LLM 决策 ∩ 策略允许 ∩ 执行能力。后两者必须是确定性代码。

---

## 2. 分层架构

```text
QQ 用户
  ↓
NapCat / OneBot 11
  ↓ 单条 WSS（正向 WS，Token 鉴权）
【传输层】协议适配器 —— 只懂协议，不懂业务
  ↓ 标准化消息段
【人格层】我是谁 —— 人设卡 / 声纹锚定 / 记忆召回(L0+L1+L2) / 关系亲疏
  ↓
【决策层】我要不要说话 —— mode / toolCalls / tts 判定 / 聚合 / 记忆写入
  ↓
【策略层】我能不能说 —— 权限 / 频率 / 预算 / 出口检查（确定性）
  ↓
【执行层】怎么说 —— 文本 / 语音 / 图片 / 引用 / 撤回
  ↓ OneBot Action
NapCat → QQ
```

**核心不变量：人格层在决策层之上。** 先确定「我是谁」，再决定「我要不要说话」。反过来会得到一个能力强但没有自我的东西。

| 层 | 能否被 LLM 影响 |
|---|---|
| 传输层 | 否 |
| 人格层 | 部分（记忆召回策略） |
| 决策层 | **是**（就是它） |
| 策略层 | 否 |
| 执行层 | 否 |

## 3. 人格规格（本体单例）

```yaml
persona:
  id: <固定 id>              # 改名会丢记忆，定下就别动
  name: <名字>
  voice:                     # 声纹锚定，运行时锁定
    model: qwen-audio-3.1-realtime-flash   # 必须 WebSocket 实时接口
    voiceId: longanlingxi       # 龙灵安希，已实测可用
    language: zh             # 改善数字/缩写/符号读法
    format: mp3
    sampleRate: 24000
    # 语气/语速/强调由 LLM 逐句决定，见 ../03-reference/tts.md
  style:
    length: short            # 群里长句是社交灾难
    emoji: low
    markdown: false          # QQ 不渲染 Markdown
  silence:                   # 什么情况下闭嘴
    - 有人正在争执
    - 话题已自然结束
    - 连续 2 次主动发言无人接话
  relations:
    owner: warm
    regular: friendly
    stranger: polite
```

**声纹锚定是人格的技术核心。** 不要每次调用随机换音色——那等于每次换个声带。

人格卡已落地：[`../../persona/whale.md`](../../persona/whale.md)（蓝色大肥鱼 / 鲸鱼娘，社区最热门底版）。
写作规范与迭代方法：[`../../persona/README.md`](../../persona/README.md)。

**人格提示词与仿真提示词两层分离**——`persona/*.md` 只写「你是谁」，工具协议、分条、潜水/唤醒规则写在仿真层。两层互不干扰。

- 优先用 `qwen-audio-3.1-realtime-flash` 的**声音设计**（`voice_prompt` 自然语言描述，无需音频样本），描述固化进人设卡；
- 或做一次**声音复刻**（10–20 秒样本，WAV 16-bit / MP3 / M4A，≥16kHz）拿到稳定音色 id 后锁定；
- 声音复刻只用自己授权的声音，别人声纹别碰。

**`voice` / `style` / `silence` 三项禁止被 LLM 修改**，列入拥有者设置通道的硬拒绝名单。

## 4. 记忆（详见 ./memory-model.md）

| 层 | 分区键 | 跨群 | 内容 |
|---|---|---|---|
| L0 本体核心 | persona | — | 人格内核（不含他人信息） |
| **L1 人物** | `user_id` | ✅ 共享 | 他是谁、偏好、与我的关系 |
| **L2 群内** | `group_id` | ❌ 隔离 | 这个群的梗、约定、共同经历 |
| L3 会话原文 | session | ❌ | 压缩归档，按需回查 |

**判定口诀**：*去掉群上下文，这条还成立吗？成立 → L1；不成立 → L2。*

三条硬约束：

1. L1 的键是 `user_id`，不是昵称；
2. L1 与 L2 **语义索引分开建**，混合索引等于开泄漏通道；
3. L2 跨域是**硬错误**，召回断言 + 出口检查双保险。

## 5. 决策契约

LLM 输出结构化决策，不是直接发消息：

```json
{
  "mode": "reply",
  "reason": "用户在问我一个问题",
  "confidence": 0.82,
  "reply": {
    "text": "……",
    "segments": [
      { "type": "text",   "text": "……" },
      { "type": "record", "path": "/abs/xxx.silk" }
    ],
    "replyTo": "1234567",
    "mention": true,
    "tts": {                  # 展开为表达对象，见 ../03-reference/tts.md
      "enabled": false,
      "text": "……",           # 口语化改写，不等于 reply.text
      "instruction": "……",    # ≤50 汉字，人格语气池内
      "tags": [],             # 白名单：[sigh] / [laugh]
      "speech_rate": 1.0
    }
  },
  "toolCalls": [
    { "name": "qq_tts", "args": { "text": "……" } }
  ],
  "aggregate": { "windowMs": 1500, "reason": "用户连发三条" },
  "memory": [
    { "layer": "L1", "userId": "123", "sensitivity": "caution", "text": "……" }
  ]
}
```

### `mode`

| 值 | 含义 |
|---|---|
| `reply` | 正常回复 |
| `silent` | 不回复（**一等公民**，不是默认失败） |
| `defer` | 等一等，看有没有人先回 |
| `proactive` | 主动发言 |
| `task` | 创建后台任务 |

### 失败模式与护栏

| 失败模式 | 护栏 |
|---|---|
| 幻觉工具名 | 工具注册表白名单 + Schema 校验，未知工具丢弃并回注错误 |
| 越权调用 | 用**回合开始时的发言人快照**复算权限 |
| 工具循环 | 单回合调用上限 + 同名重入检测 |
| 无限主动发言 | 频率闸 + 冷却 + 无回应检测 |
| 记忆串台 | 分区键断言 + 出口检查（见 ./memory-model.md §4） |

## 6. 多模态

```text
听：QQ 语音 → NapCat get_record(out_format=wav) → qwen-audio-3.0-asr-flash
看：QQ 图片 → 视觉模型描述 → 按需并入上下文（不硬塞）
想：人格层 → 决策层
说：文本 → [按需] qwen-audio-3.1-realtime-flash → wav → ffmpeg → silk → send_record
画：qwen-image → 图片文件 → send_image
```

四个模态共用**同一张人设卡**。这是「人格」与「功能集合」的分界线。

### TTS 判据

| 场景 | TTS |
|---|---|
| 情绪化内容、玩笑、安慰 | ✅ |
| 长段解释、代码、数据 | ❌ |
| 讲故事、读诗、模仿 | ✅ |
| **主动发言（proactive）** | ❌ **硬规则** |
| 群里有人正在语音对话 | ✅ |
| 深夜 / 静默时段 | ❌ |

**唯一从 LLM 手里收回的决策权**：主动发言禁 TTS。未经请求就发语音，侵扰性极强。

### 关键坑

| 功能 | 坑 |
|---|---|
| TTS | 非实时接口返回 **wav 直链，24 小时有效**，必须及时落盘；单次输入上限 **600 字符**；RPM 180，群多要有合成队列 |
| STT | **别自己解 SILK**：让 NapCat 的 `get_record` 带 `out_format` 直接吐 wav（它内置 ffmpeg 服务）；官方 ffmpeg 构建通常无 SILK 解码器；用 `vocabulary` 热词灌群昵称/黑话 |
| STT | 转写**非阻塞**：先以 `[语音]` 占位进回合，转写完再补递 |
| 生图 | 本地图片白名单必须**解符号链接**再校验，否则软链可绕过 |

## 7. 主动发言治理

**规则先于功能。功能不全是遗憾，话多是原罪。**

| 机制 | 小群首发建议值 |
|---|---|
| 触发窗口 | 5–10 分钟看一次群 |
| 静默时段 | 23:00–08:00 |
| 频率闸 | 每群每小时 ≤ 3，每天 ≤ 10 |
| 冷却 | 主动发言后 30 分钟 |
| **无回应检测** | 连续 2 次无人接话 → 该群主动降级 24 小时 |
| 话题所有权 | 有人连续对话时不插入 |
| 群级开关 | 每群可单独关 |

「无回应检测」让机器人学会「这个群不欢迎我说话」，比任何频率数字都重要。

**熟人小群额外加两条**：`/反馈 <内容>`（朋友的话直接进日志供复盘）、`/安静`（一键降级）。熟人会说真话，这是最宝贵的调参信号。

## 8. 安全红线

| 红线 | 实现 |
|---|---|
| 权限绝不交给 LLM | 策略层确定性复算，fail-closed |
| 人设卡核心字段禁改 | 拥有者设置通道硬拒绝名单 |
| 群内记忆不串台 | 分区键强制 + 索引分区 + 出口检查 |
| 记忆禁写隐私 | 正则 + 敏感度默认最高 |
| WSS 公网必开 Token | 反向 WS 无 token 时强制退回 127.0.0.1 |
| NapCat WebUI 6099 | 不暴露公网 |
| 访客禁用 DSH 内部工具 | `guestDshTools: false` |
| Token 不进记忆、不进日志 | 脱敏 + 只写字段 |

## 9. 第一周落地清单

**不要按能力顺序做（TTS→STT→识图→生图）——那会得到四个能跑的功能和一个不存在的人。**

| 天 | 做什么 | 验收 |
|---|---|---|
| 1 | 装 `dsh-qq-bot` + 单条 WSS + `auth.owners` | 私聊能收到回复 |
| 2 | 写人设卡，纯文本跑熟人小群 | 朋友说「它说话像个人」 |
| 3 | 调 `mode=silent` 判据 | 该不回的时候确实没回 |
| 4 | 接 L2 群内记忆（先只做 core.md） | 它叫得出群成员的角色 |
| 5 | 建 L1 人物记忆 + 分区键路由 + 出口检查 | 跨群不串台 |
| 6 | 声纹锚定 + 按需 TTS（仅被 @ 时） | 声音稳定不漂移 |
| 7 | 开主动发言 + 全部治理规则 | 一天没被投诉 |

节奏对了，再给它声音和眼睛。顺序反过来，你会得到一个话很多、声音很好听、但让人想屏蔽的东西。

## 10. 技术选型（不重复造轮子）

| 需求 | 用什么 |
|---|---|
| QQ 协议接入 | `@sputnikzaychik/dsh-qq-bot`（OneBot 11 正向 WS） |
| 人设卡 + 记忆引擎 | ~~`dsh-soul-md`~~ → **已否决（ADR-005）**，记忆改用 `meow-memory` |
| 会话压缩归档 | `dsh-context-zip` |
| 语义检索 | 自建薄 sidecar，L1/L2 分索引 |
| TTS | `qwen-audio-3.1-realtime-flash` + `longanlingxi`（已实测） |
| STT | `qwen-audio-3.0-asr-flash` / `qwen3-asr-flash` |
| 生图 | `qwen-image`（走 OpenAI 兼容 `/images/generations`） |

**要自己写的只有三件事**：决策契约、分区键路由、出口检查。其余都是配置。
