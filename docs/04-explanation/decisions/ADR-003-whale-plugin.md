# ADR-003：做独立插件 `dsh-qq-whale`，而不是继续改 YAML 或提上游

> ⚠️ **本文有一处论断已被证伪，阅读时请连同 [ADR-004](./ADR-004-client-half-required.md) 一起看。**
> 本文原写"DSH 会自动渲染通用表单，因此可以不做 client 半"——**这是错的**。
> 配置区必须由插件自己的 client 半注入 `plugins.bundle.config` slot；
> 且 `package.json` 里照抄上游的 client 声明指向了不存在的文件，引发过一次全站级故障。
> 正确结论见 ADR-004。

- **状态**：已接受（部分被 ADR-004、ADR-012 修订）
- **日期**：2026-11-01
- **决策者**：civer（需求方）+ 助手（架构）

## 背景

v1.2.0 之前的交付形式是一份 `config/cordis.patch.yml` + 一堆 Markdown。用户反馈：

> "这似乎都是从配置文件上进行更改，我希望能直接通过 DSH 插件/插件市场进行配置，
> 且支持在 DSH 设置页增加一项配置，用来调整插件的各项参数。"

经查 `dsh-qq-bot@0.12.8` 源码，以下事实成立（**读源码所得，非推断**）：

1. 插件导出 `Config`（`@deepseek-ai/schemastery` schema），DSH 直接把它作为设置表单来源，
   界面改动**写回 profile 的 `cordis.patch.yml`**；
2. 标了 `.volatile()` 的字段支持热改（不重挂插件）；
3. `package.json` 的 `dsh.bundle.patch` 让插件自带配置补丁，**安装即注入**；
4. `exports["./client"]` 可以挂自定义 React bundle，
   通过 `ctx.slots.inject('plugins.bundle.config')` 渲染进插件详情页的配置区；
5. `dsh-qq-bot` 自己的 `persona.text` **本来就是 volatile**，人格卡可以直接在页面里填。

也就是说：**之前用 YAML 交付是我的交付形式选择，不是平台限制。** 用户的抱怨成立。

## 决策

做一个独立插件 **`dsh-qq-whale`**（放在本仓库 `packages/` 下，成熟后再考虑拆仓库）：

- 导出 `Config` → 设置页出现「大肥鱼」配置区；
- 结构化字段（名字/性格/口头禅/雷区/音色…）+ **完整人设卡全文双轨**，
  由 `card.mode` 决定谁覆盖谁（默认 `merge`：结构化字段作为"微调层"追加在全文之后）；
- 自带 `dsh.bundle.patch`，安装即有一套可用的默认值（一键装机）；
- 提供「导出 YAML」能力，把生成的配置落进 Git 做版本与回滚；
- 使用范围：**本人 + 朋友**（不公开发布）。

## 被否决的备选

| 备选 | 为什么不选 |
|---|---|
| **继续用 YAML** | 门槛高、易出错、无法体现"人格是可调的旋钮"。用户已明确否决 |
| **提 PR 给 `dsh-qq-bot`，把人格预设做进官方** | 通用能力确实该上游化，但节奏不可控；且我们要的"大肥鱼预设"是具体人格，不适合塞进协议桥接插件。**保留为第二阶段** |
| **只写 client，不改服务端** | 人格卡需要"结构化 → 文本"的生成逻辑，放服务端才能被导出与复用 |
| **每个群一个插件实例** | 用户已确认单一本体，人格是全局单例，不需要多实例 |
| **手写 React 设置页（照抄 `dsh-qq-bot` 的 1836 行 bundle）** | **v0.1 否决**：DSH 会根据 `Config` 自动渲染通用表单，够用；而 `window.__ModuleLoader__` / `ctx.slots` 这类客户端契约在沙箱里**无法验证**，赌一个大规模手写 bundle 风险太高。留到第二阶段，等真机跑通通用表单后再决定要不要做自定义 UI |

### v0.1 的范围（明确写出来，避免范围蔓延）

**做**：`Config` 契约、结构化 + 全文双轨、人格文本生成、代码级钳制（语速 / 主动发言禁 TTS）、
导出与同步脚本、10 项本地契约测试。

**不做**：自定义 React 设置页、TTS / STT / 生图工具、自动写入 `dsh-qq-bot` 配置。

## 后果

### 必须接受的代价

1. **多一层要维护的东西**：插件有自己的版本、依赖与兼容性声明（`dsh.compatibility`），
   上游 dsh 升级到 0.3.x 时可能要跟着改。
2. **两套人格来源**：`dsh-qq-bot.persona.text` 与 `dsh-qq-whale.card.text` 并存，
   必须明确谁是权威——**本插件是权威**，上游字段视为"下游渲染目标"。
3. **两步才生效**：面板改完 → 跑 `sync-persona.mjs` → 才写进 `dsh-qq-bot.persona.text`。
   没有官方跨插件写配置 API，这一步无法自动化（见下）。
4. **真机行为未验证**：沙箱里没有 DSH 运行时，`Config` 渲染成什么样、插件能不能装上，
   都只能等真机联调。已把所有未验证项集中列在插件 README 的「已知限制」。

### 需要立即做的事

- `packages/dsh-qq-whale/` 骨架落地（schema + 生成逻辑 + 最小 client + bundle patch）
- 文档补一篇：设置页字段对照表 + "从 YAML 迁移到面板"的操作步骤
- 明确写出**待验证清单**，避免把未实测的东西当结论交付

### 第二阶段（本次不做）

- 自动同步：面板改动自动写入 `dsh-qq-bot.persona.text`（需要确认是否有跨插件写配置的公开 API，
  目前**没有证据支持**，硬写 profile 文件属于侵入行为，先不做）
- TTS / STT / 生图工具（注册到 `tools` 服务，让 Agent 直接调用）
- 自定义 client 的完整交互（预览、diff、一键回滚）
