# ADR-001：采用 dsh-qq-bot 而非自研桥接层

- **日期**：2026-10-31
- **状态**：已接受

## 背景

需要在 DSH（网页版 / 云服务器版）中接入已有的 NapCat（OneBot 11 / WSS），实现 QQ 机器人。需求包含：TTS、STT、识图、生图、权限管控、LLM 自主决定回复策略（选择性/聚合/主动回复/主动任务）。

可选路径有三条：自研桥接层、引入成熟机器人框架（NoneBot2 / Koishi / AstrBot）、采用 DSH 社区桥接插件。

## 决策

采用社区插件 `@sputnikzaychik/dsh-qq-bot`（v0.12.8），**不自研协议层，也不引入第二套机器人框架**。

自研范围收敛为四件事：人格卡、记忆分区与召回、决策契约、多模态工具。

## 理由

1. **协议适配层是高风险低差异区域**。WSS 连接、重连退避、心跳、`echo` 关联、消息段标准化、会话映射——这些逻辑与业务无关，自己做只是重复实现，且最容易出安全问题。
2. **插件已内置本方案的大部分设计**。读取其真实 schema 后确认：人格注入（`persona.*`）、主动发言全套治理（`proactive.*`：时间窗/静默时段/频率闸/最小间隔/话题冷却/dryRun）、视觉（`vision.*`）、生图（`imageGen.*`）、权限三路并集、群管理 dryRun——全部有配置项，不需要写代码。
3. **引入第二套框架会引入第二个插件生态与运行时**，与 DSH 的 Cordis 插件树形成两套治理体系，长期维护成本高于收益。
4. 插件支持 OneBot 11/12、Milky、Satori、QQ 官方机器人，**未来换协议不需要重写决策层**——这是架构上的保险。

## 被否决的备选

- **自研桥接层**：协议层代码量不小，且是安全敏感区（公网 WSS、鉴权、消息解析）。自己做意味着自己承担全部安全责任。
- **NoneBot2 / Koishi / AstrBot**：成熟，但会引入独立的插件生态、调度器与运行时。本方案的核心价值在「人格 + 决策契约」，不在协议适配，第二套框架的复杂度大于收益。
- **私有分叉插件**：分叉意味着每次上游更新都要手动合并，而协议适配恰恰是最容易出安全问题的地方。

## 后果

**好处**：协议、准入、执行三层一行代码都不用写；配置驱动；可跟随上游升级。

**必须接受的代价**：

- 受限于插件的能力边界。协议层新需求只能提上游 PR（见 CONTRIBUTING §3.1 路线 D），不能自己改。
- 配置项随插件版本变化。升级后失效的键会被自动清除并记入日志，需要跟进。
- 需要持续关注上游维护状态。
