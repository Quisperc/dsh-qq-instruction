# ADR-007：`dsh-qq-whale` 降级为「内容 + 生成器」，不装为插件

- **状态**：已接受
- **日期**：2026-11-01
- **触发**：质疑"whale 到底有什么用？既然跨插件注入有风险就不必注入，我想尽可能用 DSH 原生功能和 dsh-qq-bot 实现"

## 一、评估结论：质疑成立

把 whale 声称的价值逐项对照现实：

| whale 声称提供 | 现实 |
|---|---|
| 在设置页里管人格 | ❌ `dsh-qq-bot.persona.*` **原生就有**，且它的设置页是现成可用的；whale 的配置区依赖未真机验证的 client 半 |
| 在设置页里调节奏 | ❌ `dsh-qq-bot.proactive.*` **原生 15 个字段**，同样有现成 UI |
| 一键同步人格 | ⚠️ 靠 `sync-persona.mjs` **跨插件写配置**——正是本次被质疑的风险点，且没有官方 API 支持 |
| 结构化字段编辑 | ❌ 没有 UI（client 只读），等于没有 |
| Bot 依赖清单 | ⚠️ 需要 client 半，真机未验证 |

**它管的字段，上游原生全都有；它独有的能力，一项都没兑现。**

按 [`feature-matrix.md`](../../03-reference/feature-matrix.md) 的盘点：14 项需求里 **8 项是原生的**，
真正要自己写的只有 **TTS / STT / 记忆** 三项——whale 一项都不解决。

## 二、决策

### 2.1 whale 不作为插件安装

保留代码与文档，但**默认不装**。它从"配置插件"降级为两样东西：

1. **内容资产**：[`persona/whale.md`](../../../persona/whale.md)——人设卡本身。
   这是整个项目里**最不可替代的部分**，而它是 Markdown，不是插件。
2. **生成器**：`lib/persona.js` + `scripts/sync-persona.mjs` 作为 CLI 使用
   （`--print-card` 输出人设卡文本，手动粘进设置页的 `persona.text`）。
   **不再 `--write`**——跨插件写配置这一步取消。

### 2.2 配置回归原生

| 原打算用 whale 管 | 改为 |
|---|---|
| 人格 | 直接填 `dsh-qq-bot.persona.text`（设置页，原生 UI） |
| 节奏 | 直接填 `dsh-qq-bot.proactive.*`（设置页，原生 UI） |
| 声音 / 记忆参数 | 暂无原生对应；等有真实实现再谈 |

这一改，**"UI 与 YAML 二选一"的纠结也消失了**——设置页就是原生的，改完自动写回 `cordis.patch.yml`。

### 2.3 真正该写的是 voice 工具插件，不是配置插件

TTS / STT 是 dsh-qq-bot **完全没有**的能力（schema 里没有任何 tts/asr 字段），且：

- 它**不需要碰别人的配置**——只注册工具（`qq_tts` / `qq_asr`），Agent 自己决定调不调；
- 它符合"最薄桥接"：API 侧已全部实测（见 [`capability-report.md`](../../03-reference/capability-report.md)），
  缺的只是把合成结果落盘成 `.silk`（插件按扩展名自动当语音发）；
- 它才是"让它在群里真的能听会说"的那一块。

## 三、什么时候复活 whale 为插件

满足任一：

1. 需要**群级记忆分片**（原生没有，soul-md 也做不到，见 ADR-005）；
2. 需要把声音/记忆挂进 Agent preset（`agentPresetCustom`）——那时它是"能力提供者"而非"配置搬运工"；
3. `dsh-qq-bot` 上游接受了"人格预设导入"能力，whale 作为预设提供方。

判据一句话：**当它提供的是原生没有的能力，而不是搬运原生已有的配置时，它才配叫插件。**

## 四、代价与保留

- 代价：人格的"结构化字段编辑"暂不可得，只能编辑整篇 Markdown（可接受——人设卡本来就是散文）；
- 保留：whale 的代码、测试（25 项）、`persona/whale.md` 全部留在仓库，不删除；
- 保留：`buildPresetPatch()` 与 ADR-006 的结论，作为将来挂插件时的铺路。

## 五、教训

> 做插件之前先问：**这件事上游是不是已经有原生 UI？**
> 我这次是先写了插件，再去发现上游原生就有、而且更好。
> 顺序应该是：**先盘原生能力（feature-matrix），再决定要不要写。**
