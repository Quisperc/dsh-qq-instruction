## 3. 数据流：一条消息的完整生命周期

群里有人 @ 机器人说「今天天气怎么样」：

| # | 环节 | 在哪执行 | 做什么 |
|---|---|---|---|
| 1 | 事件上报 | NapCat → WSS | 推 `message` 事件（含 `sender` / `group_id` / 消息段） |
| 2 | 协议归一 | 插件传输层 | 解成标准化消息段，识别 `@`、图片、语音 |
| 3 | 准入判定 | 插件准入层 | 群在白名单？@ 了吗？限流通过？（不过 → 静默丢弃） |
| 4 | 会话定位 | 插件会话层 | 找到/创建 `群聊_778916943` 的 DSH 会话 |
| 5 | 人格注入 | DSH Agent | 首次注入 `persona.text`；召回 L0/L1/L2 记忆 |
| 6 | 决策 | LLM | 输出结构化决策（`mode` / `toolCalls` / `tts`） |
| 7 | 策略校验 | 工具层 | 权限复算、参数钳制、频率复算（不过 → 拒绝/降级） |
| 8 | 执行 | 插件执行层 | 调工具、生成回复内容 |
| 9 | 出口检查 | 你的代码 | 跨群泄漏扫描、隐私扫描（不过 → 拦截重写） |
| 10 | 发送 | 插件 → WSS | `send_msg` Action → NapCat → QQ |

**回程**：NapCat 返回 `echo` 关联的响应，插件确认送达；失败则按 `restart.baseMs/maxMs` 退避重试。

## 4. 层间契约

| 边界 | 传递什么 | 形式 |
|---|---|---|
| NapCat → 传输层 | OneBot 11 事件 | JSON，含 `post_type` / `message` 段数组 |
| 传输层 → 人格层 | 标准化消息 | `{text, segments[], senderId, groupId, isAt, msgId}` |
| 人格层 → 决策层 | 人设卡 + 记忆 + 关系 | 拼进 system / 上下文 |
| 决策层 → 策略层 | 结构化决策对象 | JSON（见 ./design-rationale.md §5 契约） |
| 策略层 → 执行层 | 已授权的动作 | `{action, params, constraints}` |
| 执行层 → NapCat | OneBot Action | `{action, params, echo}` |

**关键**：决策层输出的是**决策**，不是消息。这是整套架构唯一必须自己发明的东西——它让「不回复」成为一等公民，让权限能在执行前复算。

## 7. 失败与降级路径

| 故障 | 系统行为 | 你要做什么 |
|---|---|---|
| WSS 断开 | 插件按 `restart.baseMs→maxMs` 指数退避重连 | 一般自动恢复；持续断则查 NapCat/反代 |
| 鉴权失败（401） | 重连持续失败 | 核对 token；注意反代可能剥离 `Authorization` 头 |
| DashScope 超时 | 工具层返回可读错误，回合继续 | 给每个工具设 `AbortSignal.timeout` |
| TTS 失败 | **降级为文本发送** | 不要让它「沉默」——用户会以为被无视 |
| ASR 失败 | 以 `[语音]` 占位继续 | 非阻塞设计，不卡回合 |
| LLM 输出非法决策 | Schema 校验失败 → 回注错误重生成 | 上限次数后降级为纯文本 |
| 权限越界 | 策略层拒绝 + 审计落盘 | 看日志判断是模型幻觉还是配置错 |
| 记忆写入失败 | 跳过，不影响回复 | 记忆是增强，不是依赖 |

**设计原则**：任何单点失败都不得导致「机器人沉默」。宁可降级，不可消失。

## 8. 横切关注点

| 关注点 | 机制 |
|---|---|
| **鉴权** | WSS Token（`Authorization: Bearer`）+ QQ 号白名单 + 权限三路并集 |
| **最小权限** | 访客默认禁用 DSH 内部工具；`admin.dryRun` 先演练 |
| **审计** | 每次工具调用落日志：谁、在什么上下文、调了什么、结果 |
| **成本控制** | 模型分级 + TTS 按需 + 主动发言频率闸 + API Key 月度额度上限 |
| **可观测** | 日志（`logAdapterFrames` 排障时开）+ Web UI「QQ 消息」分组 |
| **备份** | `profiles/web/cordis.patch.yml`（含人设卡与 token）+ `QQ_msg/.dsh-meow/memory.db`；或用设置页「QQBot 备份」一键导出（见 ../05-handover/OPERATIONS.md §6） |

## 9. 架构不变量（不可违反）

1. **LLM 是决策者，不是授权者。** 最终动作 = LLM 决策 ∩ 策略允许 ∩ 执行能力，后两者必须是确定性代码。
2. **人格层在决策层之上。** 先确定「我是谁」，再决定「我要不要说话」。
3. **记忆分区键不可绕过。** L1 用 `user_id`，L2 用 `group_id`，跨群召回是 bug。
4. **确定性规则先于 LLM。** 权限、限流、是否响应、频率闸——都不交给模型判断。
5. **协议层不分叉。** 需要改协议适配就提上游 PR，不维护私有大分叉。
6. **单点失败不导致沉默。** 宁可降级为文本，不可让机器人消失。
