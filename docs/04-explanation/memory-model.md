# 记忆模型 · 设计规格

<!-- data-doc-status -->
> 🕰️ **本文已过期，仅作历史参考**：它描述的是 `dsh-soul-md` 的四层记忆（ADR-005 已否决）。
> 现行记忆是 `meow-memory`，按**工作区**存放：`.../QQ_msg/.dsh-meow/memory.db`，群聊与私聊共用一份。

> 需求：**跨群个人记忆**（对某个人的认识，跨群统一）+ **群内记忆**（这个群的共同经历，严格隔离不串台）。

这两者不是「两份存储」，而是**两种不同性质的记忆**，混淆会导致社死。

---

## 1. 四层结构

| 层 | 名字 | 分区键 | 跨群可见 | 恒注入 | 内容 |
|---|---|---|---|---|---|
| **L0** | 本体核心 | `persona-id` | — | ✅ | 人格内核、价值观、说话方式（**不含任何他人信息**） |
| **L1** | 人物记忆 | `user_id` | ✅ **跨群共享** | ❌ 按需召回 | 他是谁、性格偏好、与我的关系亲疏 |
| **L2** | 群内记忆 | `group_id` | ❌ **严格隔离** | 部分（core） | 这个群的成员关系、梗、共同经历、约定 |
| **L3** | 会话原文 | `session_id` | ❌ | ❌ 按需回查 | 被压缩掉的历史原文，靠 `history_*` 回查 |

一句话区分：**L1 记「人」，L2 记「我们这儿」。**

---

## 2. 目录结构

```text
$DSH_HOME/soul-md/memory/<persona-id>/
├── core.md                          # L0 本体核心（小，恒注入，不含他人信息）
├── people/                          # L1 人物记忆（跨群）
│   ├── <user_id>.md                 # 按 QQ 号，不是昵称
│   └── index.json                   # L1 语义索引（全域）
└── groups/                          # L2 群内记忆（隔离）
    ├── <group_id>/
    │   ├── core.md                  # 成员角色、长期约定、长期梗（恒注入）
    │   ├── topics/*.md              # 事件记忆（按需召回）
    │   └── index.json               # L2 语义索引（本群内）
    ├── private-<user_id>/           # 私聊是独立场域，自成一支
    └── ...
```

两个要点：

1. **L1 的键是 `user_id`，不是昵称。** 一个人在不同群可能有不同昵称，只有 QQ 号能把他认成同一个人。
2. **L1 与 L2 的语义索引必须分开建。** 用一份混合索引做召回，等于开了一条跨群泄漏通道。

## 3. 写入定向：这条记忆该进 L1 还是 L2？

这是整个记忆系统**最核心的判定**，写错就是串台。

| 内容类型 | 去向 | 判据 |
|---|---|---|
| 他的性格、偏好、职业、说话习惯 | **L1** | 关于「他这个人」，换个群也成立 |
| 我与他的关系亲疏、发生过的关键互动 | **L1** | 关系跟着人走 |
| 他在这个群的角色（群主/管理员/新人） | **L2** | 换个群就不成立 |
| 这个群的梗、内部笑话、黑话 | **L2** | 只在本地有效 |
| 某次群里发生的事件 | **L2** | 事件属于场域 |
| 群里形成的约定、规矩 | **L2** | 同上 |
| 他告诉我的一件私事 | **L1，标 private** | 跟着人走，但出口要管 |

**判定口诀**：*去掉群上下文，这条还成立吗？成立 → L1；不成立 → L2。*

> 例：「小明是程序员」→ L1。「小明在这个群是管理员」→ L2。「我们群里管发红包叫『上供』」→ L2。「小明不喜欢被 @」→ L1。

### 3.1 写入闸门

| 闸门 | 规则 |
|---|---|
| 条数 | 单回合最多 2 条（L1 / L2 合计） |
| 阈值 | 「长期有效 + 有依据」才写；一次性细节留在 L3 |
| 长度 | 单条上限 500 字 |
| 来源 | 每条必带 `source: {group_id, user_id, ts, confidence}` |
| 禁写 | 密钥/token/路径；手机号、住址、身份证等敏感隐私 |
| 幂等 | 内容 hash 去重 |
| **定向校验** | 写入前必须显式声明 `layer: L1|L2`，缺省拒绝 |

写入太勤会变成垃圾桶，写入太懒会失忆。阈值是设计问题，不是参数问题。

## 4. 信息流向与边界（最重要的一节）

### 4.1 流向规则

```text
L0 本体          → 任何场域可用
L1 人物(在场)     → 当前会话可用
L1 人物(不在场)   → 仅当话题直接涉及此人时可用，且受敏感度约束
L2 群内          → 仅本群可用，永不跨域
L3 会话原文      → 仅本会话可用
```

**L2 跨域是硬错误，不是警告。** 代码层要有断言：召回时若 `group_id` 不匹配，直接丢弃并记日志。

### 4.2 敏感度分级（L1 专用）

L1 条目按敏感度三级标记，决定它能在哪里被说出口：

| 级别 | 例子 | 出口规则 |
|---|---|---|
| `public` | 他的职业、公开爱好 | 任何场域可提及 |
| `caution` | 他的性格特点、习惯 | 他不在场时不主动提起 |
| `private` | 他告诉我的私事、情绪、秘密 | **仅在他本人参与的私聊 / 他正在说话的会话中**可提及 |

**默认最高敏感度。** LLM 标记时若未明确分级，按 `private` 处理（fail-closed）。

### 4.3 出口检查（生成后、发送前）

回复生成后做一次确定性扫描：

1. 提取回复中出现的 `user_id` / 人名；
2. 若提及了**不在当前会话**的人，检查所用 L1 条目的敏感度：
   - `private` → **拦截重写**；
   - `caution` → 降级为模糊表述或删除；
3. 若回复中出现「别的群」「我听说」「上次你们」等跨域线索，且引用了 L2 内容 → **拦截**。

**防的就是这个场景**：机器人在 A 群知道了小明的私事，转头在 B 群说漏嘴。这是跨群记忆最大的社死风险，必须在代码层堵死，不能靠提示词。

### 4.4 主动不做的三件事

- 不主动说「我在别的群听说……」
- 不推断用户没告诉它的群际关系（「你们是不是也在一个群里」）
- 不把 A 群的梗带到 B 群

## 5. 召回与合并

### 5.1 召回顺序

```text
1. L0 本体核心        → 恒注入（必须小）
2. L2 本群 core.md    → 恒注入（成员角色 + 长期约定）
3. L1 在场人物条目     → 按当前会话参与者召回
4. L2 本群 topics      → 语义 + 关键词双路召回，topK ≤ 5
5. L3 会话原文         → 仅当 LLM 主动调用 history_* 时
```

### 5.2 冲突解决

L1 与 L2 可能冲突（例：L1 说「小明很内向」，L2 说「小明在这个群很活跃」）。

**规则：L2 优先。** 当前场域的观察比跨群概括更有权威，人的表现本来就是随场域变化的。

这条规则也让系统更「像人」——在同一个群里待久了，你对这个人的印象会被本地观察覆盖。

### 5.3 召回预算

记忆注入吃 token。L0 + L2-core 恒注入部分控制在 **1500 字符以内**；按需召回部分 topK ≤ 5、每条截断。**两边都要「少而精」，否则互补变成双倍开销。**

---

## 6. 记忆投毒防护

群里有人故意喂假信息，机器人记下来，然后在别处当作事实复述——这是现实威胁。

| 措施 | 说明 |
|---|---|
| 来源标记 | 每条记 `source.group_id` + `source.user_id` + `ts` |
| 置信度 | 单一来源的断言标 `confidence: low`，复述时加「我记得有人说过」 |
| 多源加权 | 同一事实被多个独立来源印证才升为 `high` |
| 可追溯 | 有人质疑时能说出「这是 X 月 X 日在某群听到的」 |
| 人工订正 | 拥有者可查看、修正、删除任意条目 |

---

## 7. 遗忘与归档

- `topics/` 中超过 N 天未被召回且重要度低的条目 → 移入 `archive/`，不进召回池；
- L1 人物条目长期无互动 → 保留但降权（不删除，人可能回来）；
- 语义索引是**派生物**：索引坏了删掉重建，文本永远是唯一事实源；
- 群被退出 / 人已离群 → L2 归档，L1 保留。

---

## 8. 隐私权利

明文 Markdown 的一个好处是：**记忆可被审查**。

- 提供 `/记忆` 命令（或私聊查询）：任何人可查看机器人**关于自己**的 L1 条目；
- 提供 `/忘记 <内容>`：删除关于自己的记忆，立即生效并记审计；
- 拥有者可查看/修正/删除任意条目，所有操作落审计日志；
- 备份、迁移、审查都直接操作文件，不需要专门工具。

这不只是道德姿态——熟人小群里，一句「你把我说的话都记住了？」如果答不上来，信任立刻归零。

## 9. 失败模式清单

| 症状 | 根因 | 对策 |
|---|---|---|
| 在 B 群说出 A 群的事 | L2 跨越了分区键 | 召回断言 + 出口检查 |
| 把小明的私事告诉别人 | L1 private 未做出口约束 | 敏感度分级 + 拦截重写 |
| 同一个人在不同群认不出 | 用了昵称做键 | 一律用 `user_id` |
| 记忆越写越乱 | 无写入闸门 | 条数/阈值/长度/幂等四道闸 |
| 记错了还当事实复述 | 无来源标记 | 来源 + 置信度 + 可追溯 |
| 上下文爆炸 | L0/L2-core 膨胀 | 恒注入预算硬上限 |

---

## 10. 现成轮子

不要自己写记忆引擎。用插件组合：

| 层 | 用什么 |
|---|---|
| L0 本体核心 + 记忆读写 | `dsh-soul-md` 插件（人设卡注入 + 分层记忆 + `memory_append/read/rewrite/search`） |
| L3 会话原文归档 | `dsh-context-zip` 插件（`history_segments/read/search/find`） |
| 语义检索 | 自建薄 sidecar（切块 → OpenAI 兼容 `/v1/embeddings` → 余弦 topK），按 L1/L2 **分索引** |

要自己写的只有两件事：**分区键路由**和**出口检查**。前者是 soul-md 之上的一层路径约定，后者是发送前的确定性扫描。两者都不该动记忆引擎本身。
