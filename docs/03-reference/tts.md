# 语音表达层 · 设计规格

<!-- data-doc-status -->
> 📖 **未来规划参考**：`dsh-qq-bot` v0.12.8 **没有** TTS 实现（无 `tts` 配置组）。本文是选型、音色与实测资料，不是当前能力。

> 目标：让 LLM 自行决定「这句话怎么说」——语气、强调、速度、非语言表达，但受人格卡锚定与代码钳制。

---

## 0. 实测结论（2026-10-31，已用你的 Key 验证）

| 项 | 结论 |
|---|---|
| **音色** | `longanlingxi`（龙灵安希）**可用**，已合成出真实音频（样本见 `../../samples/龙灵安希-样本.wav`） |
| **模型** | 必须用 **`qwen-audio-3.1-realtime-flash`**（WebSocket 实时接口） |
| **不能用** | `qwen3-tts-flash`（HTTP）音色表里**没有**龙灵安希；`qwen-audio-3.1-tts-flash` 这个模型名在你的网关下**不存在** |

| **端到端** | TTS 合成 → ASR 转写回中文，链路已跑通 |

可直接复用：`../../tools/probe-tts.mjs`（含音色表查询与 wav 落盘）。

## 1. 音色与模型归属

**龙灵安希 = `longanlingxi`** —— Qwen-Audio TTS 系统音色，社交陪伴向，25 岁女声，**可爱甜美（Cute and sweet）**，中英双语。已实测确认可用。

> ✅ **音色 ID 已验证**：`longanlingxi` 在 `qwen-audio-3.1-realtime-flash` 下直接可用。
> 音色表中同时存在 `longanlingxi_v3.1`；若切换模型版本后报错，改用带 `_v3.1` 后缀的版本。
>
> ⚠️ **模型必须是 WebSocket 实时版。** HTTP 的 `qwen3-tts-flash` 音色表完全不同（Cherry / Ethan / Chelsie / Serena / Dylan / Jada / Sunny / Kiki / Bella / Momo / Peter），**没有龙灵安希**。这不是偏好，是硬约束。

锁定的三件套写进人设卡，运行时不可改：

```yaml
voice:
  model: qwen-audio-3.1-realtime-flash
  voiceId: longanlingxi
  language: zh          # 改善数字/缩写/符号读法（110 →「幺幺零」）
  format: mp3
  sampleRate: 24000
```

## 2. 可用参数全景

| 参数 | 范围 | 说明 |
|---|---|---|
| `instruction` | ≤ 100 计费字符（**汉字按 2 计**，约 50 汉字） | 自然语言指令：情感、语气、角色、方言、语速 |
| `speech_rate` | 0.5 ~ 2.0，默认 1 | 调节语速不改变输出 token 数 |
| `pitch` | 0.5 ~ 2.0，默认 1 | **调音调会同时改变语速和时长**；与 `speech_rate ≠ 1` 同时传时 **pitch 不生效** |
| `language` | zh/en/ja/ko/… | 语种提示，影响数字、缩写、符号读法 |
| `seed` | 0 ~ 65535 | 固定后相同文本+参数复现相同音频 |
| `format` | wav / mp3 / pcm / opus | pcm/opus 是裸流，多数渠道处理不了 |
| `sampleRate` | 8000 ~ 48000 | opus 仅支持 8/12/16/24/48 kHz |
| **细粒度 inline tags** | 86 个 | 短语/词级控制，**含笑声、呼吸、咳嗽、叹息等非语言事件** |

**计费注意**：`instruction` 本身不计入输入 token，但会影响音频时长，从而影响输出 token。

## 3. 决策契约扩展

原来 `tts` 只是布尔值，现在展开成表达对象：

```json
"tts": {
  "enabled": true,
  "text": "我才不胖呢，一点都不。",
  "instruction": "用嘴硬又有点心虚的语气，语速稍快",
  "tags": ["[sigh]"],
  "speech_rate": 1.05,
  "pitch": null,
  "emotion": "嘴硬"
}
```

### 字段说明

| 字段 | 谁决定 | 说明 |
|---|---|---|
| `enabled` | 代码为主，LLM 可建议 | 主动发言场景强制 `false` |
| **`text`** | LLM | **口语化改写后的文本**，不等于 `reply.text` |
| `instruction` | LLM（人格锚内） | ≤ 50 汉字 |
| `tags` | LLM（白名单内） | 非语言事件，见 §5 |
| `speech_rate` | LLM | 代码钳制到 0.85 ~ 1.2 |
| `pitch` | LLM | **与 speech_rate 互斥**，见 §6 |
| `emotion` | LLM | 从人格卡语气池选，见 §4 |

---

## 4. 语气池：给 instruction 一个人格锚

**完全自由发挥会跑偏**（它会写出「用愤怒的语气」这类出戏的指令）。正确做法是从人格卡的固定语气池派生：

| 情绪 | 对应 instruction 模板 | 触发场景 |
|---|---|---|
| 嘴硬 | 「用嘴硬但有点心虚的语气，语速稍快」 | 被说胖、被拆穿 |
| 得意 | 「用有点小得意的语气，尾音上扬」 | 被夸、答对了 |
| 懒散 | 「用懒洋洋、快睡着的语气，语速偏慢」 | 犯困、不想动 |
| 委屈 | 「用委屈巴巴的语气，声音轻一点」 | 被冤枉、被忽略 |
| 认真 | 「用认真、清楚的语气，语速正常」 | 真的在解释事情 |
| 害羞 | 「用有点害羞、声音越来越小的语气」 | 被直球夸奖 |
| 吐槽 | 「用吐槽的语气，带点无奈」 | 群里出现离谱发言 |

**规则**：LLM 优先从池里选；确有需要可自由写，但必须与人格卡描述一致。代码层做长度校验（≤ 50 汉字）。

---

## 5. 非语言标签：这代模型的杀手锏

86 个细粒度标签里有**笑声、呼吸、咳嗽、叹息**这类非语言事件——**这是活人感的最大杠杆**，傲娇人设尤其吃这套。

建议给 LLM 的白名单（先只开这几个，跑顺了再扩）：

| 标签 | 用在哪 | 频率上限 |
|---|---|---|
| `[sigh]` 叹气 | 被拆穿、无可奈何、懒得解释 | 每段最多 1 次 |
| `[laugh]` 轻笑 | 觉得好笑、吐槽后 | 每段最多 1 次 |
| `[breath]` 呼吸 | 长句中间换气 | 少用 |

**不要开的**：咳嗽（听起来像生病）、哭腔（群里太重）。

**代码层强制**：标签必须来自白名单；单条消息标签总数 ≤ 2；同一标签不连续出现。

---

## 6. 钳制规则（代码层，LLM 不可越过）

| 规则 | 原因 |
|---|---|
| `speech_rate` 钳制到 **0.85 ~ 1.2** | 接近 0.5 或 2.0 会明显过慢/过快，出戏 |
| `pitch` 与 `speech_rate` **二选一** | 同时传（rate ≠ 1）时 pitch 静默失效——这是 API 硬约束，代码必须消歧，否则你以为调了其实没调 |
| `instruction` 长度 ≤ 50 汉字 | 超出返回 400 |
| `text` ≤ 600 字符 | 接口上限，超了要分句合成再拼接 |
| `tags` 白名单 + 数量上限 | 防止滥用 |
| 单条语音时长上限（建议 60 秒） | 群里长语音是社交灾难 |
| **主动发言强制 `enabled: false`** | 未经请求就发语音侵扰性太强 |
| 静默时段（23:00–08:00）强制 `false` | 语音会外放 |

---

## 7. TTS 文本 ≠ 回复文本（最重要的坑）

书面文本直接念出来非常怪。LLM 必须输出**独立的 `tts.text`**，做口语化改写：

| 书面 | 口语 |
|---|---|
| `233` | 二百三十三 / 哈哈哈 |
| `www` | 笑死 |
| `(￣▽￣)` | （删掉，改用 `[laugh]` 标签） |
| `【图片】` | 删掉 |
| `**强调**` | 删掉标记，改用语气 |
| `https://…` | 删掉（本来就不发链接） |
| `1/3` | 三分之一 |

**如果省掉这一步，语音会念出「反斜杠星」这类东西，一秒出戏。**

---

## 8. 缓存与成本

- `seed` 固定后，相同文本+参数复现相同音频 → 可做**音频缓存**（同一个人设的常用短句命中率很高）；
- 缓存键 = `hash(text + voiceId + instruction + tags + rate + seed)`；
- 输出侧：音频时长越长，输出 token 越多 → **短句不只是社交美德，也是省钱手段**；
- 群多时要有**合成队列**（RPM 180）。

---

## 9. 完整链路

```text
LLM 输出 tts 对象
  ↓
代码层：enabled 硬规则 → 长度/范围钳制 → 标签白名单 → pitch/rate 消歧
  ↓
合成：model + voiceId + text + instruction + tags + rate + seed
  ↓
wav/mp3 → ffmpeg → silk/pcm（QQ 只认这个）
  ↓
send_record
```

最后一步**没有现成实现**：`dsh-qq-bot` v0.12.8 只把收到的语音渲染成「[语音]」占位，
**没有任何发语音的路径**（没有 `record` 段构造、没有 `send_record` 调用）。
所以要做 TTS，必须自己写：

1. 构造 OneBot `record` 消息段（`{"type":"record","data":{"file":"<url>"}}`）并通过适配器下发；
2. 音频必须托管成 **NapCat 能访问到的 URL**（`file:` 本地路径在远端读不到）；
3. 不要用 `{"type":"tts"}` 段——多数实现不支持，且会静默失败。
