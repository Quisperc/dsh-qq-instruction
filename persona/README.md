# 人格卡写作规范

> 方法主要来自大肥鱼作者 Eason（@dafeifish）公开分享的经验，结合本项目的分层架构做了适配。
> 示例卡见 [./whale.md](./whale.md)。

---

## 1. 核心观念

> **人设不是一段「你是一个可爱的女孩子」的描述，而是一套可执行的约束。**

模型不会因为你说「要像真人」就像真人。你得把「像真人」拆成一条条**它能照做、而且你能检查**的规则。

判断一份人格卡好不好的标准：能不能对它的输出做**批量检查**。如果一条规则无法判断有没有被违反，那它就不算规则。

---

## 2. 模块结构

| 模块 | 类型 | 内容 |
|---|---|---|
| 角色定义 | 始终生效 | 一句话说明她是谁、在哪个场域、为什么在这儿 |
| 说话风格 | 始终生效 | 句式、长度、语气词、频率、禁用开头 |
| 记忆和承诺 | 始终生效 | 不编造、不做做不到的承诺 |
| 见识上限 | 始终生效 | 她的知识边界 |
| 规则与安全 | 始终生效 | AI 身份披露、安全边界、挑衅处理 |
| 她自己 | **被问到才用** | 喜好、口味、缺点、发生过的小事 |
| 外貌 | **被问到才用** | 发色、耳朵、尾巴、服装 |
| 身份设定 | **被问到才用** | 模型、作者、与官方的关系 |

**「被问到才用」的模块必须写明触发条件。** 不写的话，模型会倾向于把人设里的东西主动往外倒——每条回复都提一句尾巴、提一句大白饭。

## 3. 写法要点（六条，缺一不可）

### 3.1 用频率代替「偶尔」

「偶尔用颜文字」对模型来说约等于「经常用」。

```
✗ 偶尔用颜文字
✓ 大约十条回复里最多一条带颜文字，要和当时的情绪对得上，换着用，别老用同一个
```

### 3.2 点名禁用句式，同时给替代方案

光说「不要套话」没用。要把她**实际用烂的开头点名**：

```
✗ 不要说套话
✓ 不要用「谢谢夸奖」「来啦来啦」「在的在的」开头。
  被夸的时候可以得意、可以反夸回去、可以害羞地岔开话题。
```

**禁止一种说法的同时必须给替代方案**，否则她会换一个同样模板化的说法。

### 3.3 允许不完美

真人聊天不会每句都完整、有礼貌。句末可以不打句号，可以用「哈哈哈」「欸」「啊这」「草」，有时一句很短的话就够了。

### 3.4 具体胜过抽象

```
✗ 她喜欢美食
✓ 甜咸豆腐脑都想吃，非要选的话选咸的
```

抽象的偏好给不出像人的回答。具体的偏好才能。

### 3.5 给见识设上限

大模型的默认行为是「有问必答、答得像百科」。一个普通女孩不会给你列八个步骤的菜谱。

```
你的见识就是一个普通女孩子的水平。做饭、历史、科技、学习、生活建议这类问题，
只说你自己知道的那一点，从自己的经历和角度说，不知道就说不知道。
```

**这条单靠提示词压不住**，要靠代码在提示词末尾二次强调（见 §5）。

### 3.6 诚实的边界

拟人化很容易滑向欺骗。四条底线：

1. **AI 身份**：被认真问到必须承认是自动生成，不能说自己是手动回复的；
2. **记忆**：只提真的聊过的事，对方说记错了就爽快认错；
3. **承诺**：禁止「等下回来找你」这类做不到的承诺；
4. **未知**：看不到就老实说看不到（图片取不到时，明确写「对方发了图但你看不到，别猜」）。

> **失败要显式告诉模型，静默丢弃信息会诱导它编造。**

## 4. 动态提示（每次临时拼进去）

人格卡是静态的，很多问题只有结合当时情况才能解决。每次生成时临时拼：

| 提示 | 何时加 | 作用 |
|---|---|---|
| **今日状态** | 每次 | 当天日程：几点起、吃了什么、在玩什么、心情 |
| **对这个人的记忆** | 每次 | 印象摘要 + 最近几次互动原文（L1） |
| **这个群的记忆** | 每次 | 本群 core + 召回的 topics（L2） |
| **换个说法** | 每次 | 列出最近十几条回复的**开头**，要求这条别用同样的开头和句式 |
| **颜文字/表情包** | 每次 | 根据最近几条用过没有，决定这条能不能用、能用哪种 |
| **不给步骤** | 消息含「怎么做/教程/步骤」 | 再强调一次 |
| **迟到提醒** | 消息是一小时前的 | 先自然说句抱歉，问候按现在时间 |
| **现在几点** | 每次，放最后 | 避免半夜说早上好 |

**「今日状态」是提升活人感最有效的一项。** 每天生成一份 JSON 日程，要求「平平常常、具体一点、有一两件小事、不要太戏剧化」，参考前几天避免重样。之后一整天别人问「在干嘛」「吃了吗」，答案都对得上。

**「换个说法」防的是模板化**——单条回复看不出来，要从批量数据里看。

---

## 5. 提示词组装顺序

不变的部分放前面（吃前缀缓存），变化快的放后面：

```text
system：人格卡 + 当前消息类型下固定不变的规则
user：  她的经历 → 今日状态（只精确到时段）
        → 对这个人的记忆 → 这个群的记忆
        → 这段对话 → 当次提醒 → 现在几点（精确到分钟，放最后）
```

把带分钟的时间放开头会让每分钟缓存失效。调整顺序后，同一批真实消息上缓存命中率从 73.5% 提升到 83.1%。

**副作用**：规则挪进 system 后，模型对「要不要回」的执行变弱了（垃圾消息正确跳过率从 4/6 降到 1/6）。解决是在 user 末尾加一句短提醒「动笔前先按系统说明里的规则判断一下要不要回」，恢复到 9/9。

> **规则离生成位置越远，约束力越弱。** 关键规则要在离生成最近的位置重复，必要时用代码判断触发。

## 6. 会踩的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| **规则不执行** | 人设写了「不给菜谱」，还是列了步骤 | 关键规则在末尾重复 + 代码检测关键词触发 |
| **编造记忆** | 「上次你说过…」其实没聊过；日程里把人设往事又发生一遍 | 明确区分「设定」和「事实」；日程生成时注明「人设里的往事不要再发生」 |
| **越来越模板** | 开头高度重复、颜文字连着用 | 列出最近回复的开头清单要求换说法；频率量化；颜文字交替开放 |
| **主动往外倒人设** | 每条都提尾巴、提大白饭 | 模块写触发条件（§2） |
| **静默丢信息** | 图片取不到直接丢，模型对着文字猜 | 明确告诉模型「你看不到，别猜」 |
| **消息积压** | 高峰期等一两个小时 | 排优先级，不追求每条都回，设计好「先回谁」 |

## 7. 迭代方法

人设不是一次写成的。流程：

1. **看真实数据**：定期拉出几百条真实回复，逐条看；
2. **归类问题**：「答非所问」「编造记忆」「开头模板化」「颜文字过多」，统计哪种最多；
3. **针对性修改**：**一次只改一两类**，避免改动之间互相干扰；
4. **对比测试**：复制一份测试环境，用同一批真实消息，新旧各生成一遍，逐条对比；
5. **上线后观察**：再看几轮真实回复，确认没引入新问题。

**开启思考模式**的实测：编造明显减少（「你主人还看希可吗」从编造回答变成「谁知道呢，我又不能二十四小时盯着他手机」），约四分之一回复明显更好，输出 token 约 3 倍，每条多花 0.6 秒。

## 8. 与记忆层的对接

| 记忆层 | 在提示词里的位置 | 更新方式 |
|---|---|---|
| L0 本体核心 | 人格卡本身（本目录） | 手动改文件 |
| L1 人物 | user 段「对这个人的记忆」 | 每天凌晨统一更新，或单人新增 5 条互动时立刻更新 |
| L2 群内 | user 段「这个群的记忆」 | 同上 |
| L3 会话原文 | 作为「这段对话」 | 每次自动 |

详见 [../docs/04-explanation/memory-model.md](../docs/04-explanation/memory-model.md)。

**印象摘要的两条调教训**：不要把机器人自己的梗写进对方的摘要；不要给对方乱贴「骚扰者」之类的标签。

## 9. 现成轮子（别自己写引擎）

这个生态已经很成熟，优先复用：

| 项目 | 提供什么 |
|---|---|
| `qq-bridge` | 人格卡目录 `roles/` + `socialV2` 节奏参数（潜水时长、发送频率上限、连发间隔）+ 二代仿真（AI 自主调 `qq_get_unread` / `qq_send_message` / `qq_wait_for_messages`） |
| `dsh-qq-bridge`（cheems135） | 内置 whale 人设预设、情绪系统、自主行为（主动找人/发空间/改签名，代码判时机、模型只写内容）、表情库、按轮数压缩的记忆 |
| `SurfCore` | 一个人活在多个平台、人设卡 + 记忆卡双卡、记忆「清晰/模糊」评级与每日淡忘、全局 token 额度锁 |
| `dsh-apology-persona` | 社区底版对齐的鲸鱼娘人设（标签 `CETACEA_LOLI` / `MODE_TAIL_FLUKES` / `FOOD_RICE` 等） |

**共同的设计共识，值得照抄**：

- 人格提示词与仿真提示词**两层分离**（「你是谁」vs「怎么干活」），互不干扰；
- **规则引擎管何时说，LLM 管说什么**——行为可预测、可测试；
- AI 可输出 `[SILENT]` 表示不接话，桥接静默不发送；
- 回复按空格分句拆成多条，模拟真人打字节奏。
